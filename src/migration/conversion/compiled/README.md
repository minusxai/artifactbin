# Offline compiled conversion

These modules are explicit migration tools, never runtime fallbacks. `compileArchivedStatic` emits static HTML/CSS; `compileArchivedLocal` emits HTML/CSS plus a self-contained ordinary JavaScript bundle. Both run the archived compiler only in a bounded subprocess with isolated environment variables. The product server does not import them.

The local route currently admits scalar `Value` declarations in `Helmet`, exact archived static/layout kit modules, scalar `Button set={{field: value}}`, `Input`, `Textarea`, native bound input/select/textarea, and scalar text references. The single Apollo JSON field `compiledPage` owns all page scalar state. Hydration first claims the default SSR tree, then projects the saved state; this order is required to avoid stale initial text after reload. Each write merges through an Apollo update callback, preserving other fields.

Local SQLite queries over scalar Values and their Number/Cell projection are also admitted. The migration compiler validates and evaluates their default plan, then emits the ordinary JavaScript SQLite engine and embedded WASM. The browser derives tables from Apollo state and rejects stale query responses. External sources, viewer/clock built-ins and shared mutations are blocked; query result tables are derived, never a second mutable state store. The SQLite adapter uses a narrow pure contracts facade to omit unrelated platform route initialization.

Inline table Values persist typed scalar rows through the same Apollo viewer state. Read-only Imports require exact trusted metadata bindings and use named Apollo backend queries. Rows stay in memory, never in page source or viewer persistence. Live reads latch a dataset version and generation across every pagination window and table; one bounded restart discards a changed snapshot. Pinned reads additionally require the manifest version. Shared byte, row and deadline budgets cover retries. Fixed remote Apollo watchers refresh the complete transient snapshot after server changes and reconnects; failed reads visibly clear prior results.

The importer may explicitly set `datasetUnavailable: {reason: "historical-binding-unavailable"}` for a historical revision whose original data authorization cannot be established. This mode emits a permanent visible limitation, no backend links or requests, and no query engine. It is classified renderable with `historical-data-unavailable` provenance, never functionally complete. Current revisions must use actual bindings.

`compileArchivedAuthor` is a separate explicit whole-document route. It admits one supported Helmet script, compiles it without server evaluation, preserves trusted layout and fallback markup, and mounts exported components only in the browser. A single Solid runtime serves kit and authored components. Named author signals persist through Apollo `authorSignals`; declared Values use `compiledPage`; query results remain derived and transient. Failed mounts restore fallback content and show an error.

Registered dataset mutations require exact importer-supplied operation metadata and an already linked backend namespace. Only bounded scalar `Button run`/`args` controls are admitted. The browser sends operation names, typed parameter snapshots and fresh request IDs through fixed Apollo documents; mutation SQL never enters the HTML. Confirmed commits reset only submitted fields that the viewer has not changed and refresh transient datasets. Unknown outcomes retain the original request ID and arguments for an explicit Reconcile save action. Row-dependent writes and unsupported mutations remain blocked.

Static Question table/single-value views retain the kit renderer. Vega charts require finite offline plans and an interpreter-only browser renderer with explicit resource and event boundaries. Templates, unresolved recipes, external resources and undeclared chart behavior are refused.

Arbitrary unsupported expressions, custom `Select`, SlideDeck and other undeclared kit behavior remain blocked. A failed capability check returns no HTML. There is no implicit static fallback. Functional classification applies only to explicitly admitted capabilities.

The migration bundle resolves archived compiled kit and Solid modules from the archived build manifest, replaces `@mx/boot` entirely, and externalizes only `@afbin/apollo`. It has no network dependency on archived modules. Provenance records the archived build and actual contributing bundle modules. Legacy source and subprocess output are bounded to 8 MiB and 32 MiB; final HTML additionally obeys the product’s unchanged 4,000,000 byte import limit; subprocess execution is limited to 60 seconds. The source is parsed and capability-checked before invoking the archived compiler; author code is not evaluated.

The caller must choose this strategy explicitly. All corpus content and browser proof files belong outside the repository. A modified example proves adapter behavior only; it is not evidence that an unchanged corpus document has migrated.

`resourceMap` applies only to static output: each exact old image URL maps to a verified canonical ACL media endpoint supplied by the importer. Shape validation grants no authorization. Each srcset candidate is resolved independently and retains its width/density descriptor. Missing candidates, duplicate or mixed descriptors, and invalid targets remain blocked. Local hydration requires source and SSR media mapping together and does not yet support this port.
