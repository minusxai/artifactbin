# Native Codex/Claude terminal submission

The managed terminal adapter now treats a complete line ending in CR as one bracketed paste for Codex and Claude, regardless of whether it came from the terminal relay keyboard source or an artifact comment. It writes the exact payload without CR, writes the paste-end marker, waits 200 ms, and then writes one separate CR if the PTY remains writable. Incomplete/raw keyboard chunks and unmanaged/provider-shell input keep their existing behavior. Comment payload transformation still occurs before framing.

The selected CLI runner test file passed 19/19 tests, including large keyboard/comment paste framing, one submit after the settle gap, suppression when the PTY exits during settling, duplicate relay delivery, and raw text/CR/Escape chunks. `npm run validate` passed.

The exact built worker proof used Codex CLI 0.160.0 and afbin 0.4.54 (worker image `ghcr.io/minusxai/artifactbin-server-runner-worker@sha256:21d8fe2ba2daefb0457dbf2f25ee815a41cf0fcf2fcbf8cb3f3b3901fde0091d`). Raw text plus CR failed to submit at both 61 bytes and 7,081 bytes over the 45-second observation window. Bracketed paste with a 200 ms gap submitted both exact markers (3.276 s and 3.592 s). A 7,081-byte bracketed comment also submitted with immediate CR (3.319 s), as did the 200 ms case (1.820 s), so this proof supports the paste boundary but does not establish that 200 ms is necessary. It remains useful as a settle interval and to prevent sending Enter after PTY exit. The rehearsal log is `evidence/codex-input-isolated-rehearsal.log` in the production task evidence directory; it reports cleanup complete with 2 disposable volumes created and deleted.
