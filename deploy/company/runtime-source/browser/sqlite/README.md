# Debian 13 SQLite session backports

Selective consumer inputs: `build.sh`, `prepare.py`, `sources.json`, `provenance.json`, `check-sqlite.c`, `verify.sh`, and the complete `patches/` directory. Do not copy source archives, source trees, native binaries, or host logs. No new upstream SQLite major/minor version, public API, or Debian build-feature change is introduced.

Exact source: Debian sqlite3 3.46.1-7+deb13u2, four checksum-verified official Debian source files. The existing Debian patch series and packaging rules remain intact. Binary version becomes 3.46.1-7+deb13u2+runtime1. Backports retain honest source/upstream version metadata; advisory scanners may continue to report version-based matches. Installed receipt is `/usr/share/sqlite-runtime/runtime-source.json` with adapted patch bytes alongside it, outside slim-image excluded documentation paths.

Fixes: upstream e807d4e fixes CVE-2026-50812; upstream 869a51a fixes CVE-2026-50813. Their original fixing-tree session code also supplies bounded varint, table-header and record-buffer prerequisite guards. Merely adding the changed varint mask is insufficient on this older tree: exact upstream sessionC-9.0 otherwise returns NOMEM, rather than CORRUPT. These prerequisites are copied from the pinned fixing tree; no invented new API or speculative test payload. The session9 fixture omits only a preceding `db2 close` belonging to a newer pre-existing test, which this Debian source lacks.

CVE-2021-45346 is disputed and remains upstream-unfixed; this recipe does not claim to resolve it. No absence of an established application trigger is used as a waiver.

## Builder contract

Use an isolated Debian 13 builder with the same originally installed SQLite package/source versions as the final image. Capture the final image's package names BEFORE any build/tool dependencies, and provide that file as `SQLITE_RUNTIME_PACKAGE_LIST`. Packages names are unqualified (strip `:amd64` etc). Use an actual final-profile inventory, not an assumed generic list. Core Company has only libsqlite3-0; evaluator generic has sqlite3 and libsqlite3-0. A consumer with no libsqlite3-0 exits without introducing SQLite.

Only ordinary Debian base utilities and apt are needed initially. The helper freezes original library ELF bytes, SHA256, controls and package profile before installing python3, patch, dpkg-dev/binutils, build-essential and CA trust in the builder. Export symbols and compile options are measured against those frozen original bytes (LD_LIBRARY_PATH), even if apt changes the live builder library. These are builder-only prerequisites; no Python is added to the final image. The baseline checker uses the generated source header and links directly to the frozen original SONAME file after Debian binary packaging, without requiring the package under build to depend on its own development package. Original binary-arch ends in dh_builddeb (no clean); generated header and libtool output are explicitly required before tests. Call `sh /runtime-build/sqlite/build.sh`. The helper installs original Debian build dependencies, builds original Debian architecture-specific packages, explicitly runs three upstream session suites, and builds the public native checker. `/out/*.deb` contains replacements ONLY for originally present package names; build-only development/Tcl/etc packages never enter the final image. `/out` must be dedicated to this helper or shared package collection with disjoint names.

Install emitted packages together in the final runtime (`dpkg -i /out/*.deb` in a dedicated mount; no apt upgrade that restores the old packages). Keep normal libc/SQLite SONAME and Debian package ownership. Mount proof output read-only and execute `sh /out/verify-sqlite.sh /out` in the actual final runtime. This requires only shell/core utilities and the native executable; no dev headers, binutils or Python are added to final images. Any already-installed Python receives an additional real sqlite3 in-memory query assertion. Consumers must preserve `/out/sqlite-runtime-package-names`, compile-option/export inventories, all test logs, native checker and provenance as validation artifacts, outside the shipped product if desired.

Final verification requires the exact replacement package version, SHA256 equality with the actual stripped library extracted from the emitted Debian package, installed receipt bytes, unchanged compile options, resolution of every original exported symbol name, ordinary DB/FTS5/integrity-check/session roundtrip, and the exact upstream concat corruption case. Export-name checks are not complete ABI proof; ordinary actual consumer integration remains required. The two source regression suites additionally exercise the exact upstream apply_v2 case before packaging.

## Evidence and limits

`clean-patch-proof.json` binds all zero-fuzz patch applications from clean checksum-verified source to the host-tested source. `host-validation.json` records macOS arm64 upstream session tests and ASAN/UBSAN native checks. Host proof does not establish Debian packaging or final Linux functionality. No local Docker build was performed; consumer hosted Linux gates remain mandatory.
