# Pagegi
Keep the product small: a page is a normal HTML file that loads one script, the core (`/af/v1/core.js`), and one server hosts, shares and comments on it. There is no CLI: agents work over the HTTP API and the scripts in `skills/pagegi-author/scripts/`. No in-app source editor.

The author skill in `skills/pagegi-author/` is the contract. `SKILL.md` and `references/` say what pages may do and what the HTTP API returns; `test/v2/` checks the product against them. Change the skill, its tests and the code together, and keep its examples working.

Pages keep all their state through `client` from `@afbin/apollo`, never through globals the platform injects: local state at the top level belongs to each viewer (kept in their browser, never shared), and data viewers share goes through backends under their `data-af-name` (each backend file has a platform-kept store, `caps.store`). The platform's markup is `data-af-*`: `data-af="meta"`, `data-af="state"`, `data-af="core"` and `data-af="design-system"` blocks, `data-af-id` node identities, and `data-af-dark` / `data-af-design-system` on `<html>`. Preserve stable `data-af-id`s (never reuse a removed one) and every saved page version. Treat page scripts as untrusted relative to credentials: they run on a per-page runner origin, never the platform origin, and account tokens never belong in a page or a downloaded file.

Run `npm run validate` and `npm test` while working and `npm run check` before completion (it needs Postgres, Playwright browsers and the `pagegi-backend:local` image; see README). Rebuild and commit `skills/pagegi-author/scripts/` with `npm run build:af` after changing `src/af-script/` or `src/page/`. Tests must exercise behavior, not implementation details. Never commit credentials, private artifact links, or generated test data.

Define or update TypeScript interfaces first, then write failing behavioral tests against those contracts, then implement. Prefer the pure model for edge cases and injected clocks over starting the app. Keep only integration-specific checks in browser/server tests.
