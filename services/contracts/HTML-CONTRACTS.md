# HTML contract handoff

These contracts extend the original product. `HtmlPublication<A>` and `PageOperations<A>` take the original app-owned `AccessActor` as A, including userId, tokenId, email, documentEditor and optional groupId. They do not accept an iframe-supplied Actor. Keep the original `effectiveRole`/dataset policy functions authoritative.

`HtmlNodeAnchor` is an explicit `{kind:'html-node',v:1}` extension to annotation persistence, tied to immutable revision plus stable data-af-id. It is never an AST path. Original annotation UI/store integration owns this extension and preserves legacy non-HTML target types separately. Decoding an anchor does not authenticate its sender.

Custom backend links pin backend versions. Dataset links explicitly use live or pinned mode. Archived pages preserve this choice: live bindings continue querying authorized current data; pinned bindings read their recorded revision and reject writes. All reads repeat current ACL; a historical snapshot is not a durable authorization grant. Publishing a pinned binding must fail if the dataset storage cannot supply that revision.

Every dataset link mounts that dataset's generated GraphQL API (Hasura's shape, `services/app/lib/dataset-graphql/hasura.ts`): a link named records adds the roots records, records_by_pk, records_can and the insert_/update_/delete_records mutations flat at the top of the page schema, for the page reader's role through the page. There are no aggregate roots: a page that links a dataset also answers the reserved read-only `_sql(sql, params): {columns, rows}` over its linked datasets as the reader, refused for a table whose rule does not allow SQL (`allow_aggregations`). The dataset's v3 rules decide which roots, columns and rows each role sees and may write; the page as `X-Hasura-Page-Id` is a session variable, never write authority. Public page read access alone is insufficient dataset-write authority. A mutation writes one dataset atomically under its Idempotency-Key and reports committed, rejected or unknown per root; unknown outcomes are never retried automatically.

Publication tests must cover preservation of HTML outside platform-owned edits, monotonically increasing node allocation across all historical versions, stale-head CAS, idempotent receipts and atomic page/backend link commit. Operation tests must cover namespace collisions, authorization before invoke, ordered mutations and unknown/rejected outcomes. Integration owners implement those tests with real original ACL/transaction adapters. This contracts-only change does not claim these implementation invariants are already tested.

Native slide exports use explicit `data-af-slide` attributes on author-owned sections. `slide=N` selects the Nth laid-out marked element outside deck chrome in document order (hidden miniatures do not count; a stacked deck's hidden inactive slides do) and draws it alone. A missing slide returns `no_slide` and the count. Whole-page export remains the full HTML body.

Native social preview metadata lives in `<head>`: `<meta name="artifactbin:og-crop" content="x=0;y=0;width=1600">` selects a 40:21 crop in the canonical 1600px page layout. An optional `<meta name="artifactbin:og-image" content="ref:IMAGE_ID">` selects an image the publisher can read; the publication records that admitted image reference. `artifactbin:og-image-crop` uses the same coordinate grammar against the image's canonical 1600px width. Metadata changes use the original HTML publication endpoint with `expectedVersion` and `expectedState`; a conflict requires review and never retries the replacement automatically. Existing metadata keeps its stable `data-af-id`.

HTML downloads embed admitted raster image `ref:` sources as data URLs after rechecking the downloading reader's current image ACL. Missing or unreadable images return the uniform 404; unsupported stored image MIME types return 415. The 25 MiB file limit includes embedded bytes and the runtime. Existing authored data images and inline SVG remain unchanged; arbitrary remote URLs are not fetched during download. No account credentials or capability URLs are added to the file.
