People review a page by commenting on it, so a create or edit (even one line) is unfinished until its comment watch runs; do not ask first. After your first push, or once local preview runs, start `afbin watch <url|file> --comments --json` once with a tool that wakes you on each output line (a monitor); keep it running after your reply until the session ends or the user says stop; never start a second. A plain background job is not a monitor: its output lands in a log nobody reads, so comments go unanswered. Without such a tool, check `afbin comment <url|file> --json` between work steps instead. `author.you` comments are your user's requests (weigh others'): make the change, push, then reply `afbin comment ID --thread ANNOTATION_ID --body 'What changed'`.
