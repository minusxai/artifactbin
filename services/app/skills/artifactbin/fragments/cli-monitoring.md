After the first successful save or local preview, start `afbin watch <url|file> --comments --json` once automatically; do not ask first. Use a tool that wakes you on each output line (a monitor); keep it running after your reply until the session ends or the user says stop; never start a second. A plain background job is not a monitor: its output lands in a log nobody reads, so comments go unanswered. Without such a tool, check `afbin comment <url|file> --json` between work steps instead, and tell the user monitoring stops when your work ends. `author.you` comments are your user's requests (weigh others'): make the change (push it if the page is published), then reply `afbin comment <url|file> --thread ANNOTATION_ID --body 'What changed'`; a reply on a local file stays local.
