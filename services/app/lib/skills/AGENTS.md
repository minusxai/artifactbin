# The author skill

This card also governs every edit under `services/app/skills/`. `lib/skills` loads that tree, validates it,
renders it for an origin, packs the skill zip and serves `/llms.txt` and `/llms/<topic>`. The skill tree holds
only the skill: no loose files at its root (`loadSkillSources` throws).

## Rules
- Test contracts, never prose. Pinned copy, docs and errors have tests and gates (`buildQuickSheet`,
  `agentDiscovery`, `renderDoc`, exact text): find them and update them with the copy.
- Caps, enforced by `validateSkillTree` in `__tests__/skill-tree.test.ts`: rendered `SKILL.md` ≤ 20,480 B,
  each reference ≤ 8,192 B, every file ≤ 500 lines, `## Read first` ≤ 2,500 B, the listing ≤ 6,144 B, and a
  `## Contents` past 100 lines with three or more sections. Archive and public budgets have their own tests.
- One rule per concept in one place: `retired-phrasing.test.ts` refuses retired and contradictory sentences
  across everything an agent reads. Shipped code keeps a header and 200 lines of 100 columns
  (`skill-code-shape.test.ts`); `components/` is generated by the reader build, never hand-edited.
- Verify on the task's own dev server only, then `npm run eval` shows an agent using the change.
- Evals: `evals/` is the private, gitignored `minusxai/artifactbin-evals` repo; its README is the guide. Copy it
  from `~/projects/artifactbin-evals/evals`, never symlink; a copy lacking `evals/README.md` is stale.
  `npm run eval -- --tasks <name>` runs against the dev server (`--deployment`, `--help`).
- Local evals use the real product contract:
  - Supply the target origin and the exact candidate skill assets independently; package and skill edits reach
    the next run. Test installed and fresh-install paths against the candidate; HTTP discovery, guides, auth and
    API use the target.
  - Local and deployed briefs and scorers are identical: no local-only prompts, auth bypass, production
    deployment or published/latest fallback. The harness delivers the local OTP; the agent follows normal auth.
  - Isolate harness homes, credentials and data. Record server/source revision, candidate and skill hashes and
    harness, model and settings; invalidate stale assets when a relevant input changes.
  - Reproductions and timings (Pi included) reuse this harness, target/candidate, isolation, auth, traces and
    metrics: add scenarios or capabilities, never separate runners. URL probes use verbatim user requests.
  - Enforce caps outside model context; no evaluator, scorer or answer hints via prompts, hooks or config.
    Preserve native replies and private instruction evidence.
  - Compare baseline and candidate with identical scenarios and settings, retaining failures and missing
    metrics. Changed harness semantics need a matched new baseline.
