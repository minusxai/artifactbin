# CI merge and deployment policy

Pull requests require two parallel checks: `fast (validate)` runs TypeScript and architectural boundaries, and `fast (test)` runs the pure test suite. Each matrix lane restores cached npm dependencies and installs with `npm ci`; only validation restores incremental TypeScript metadata. Neither lane provisions a database, Docker image, browser, or application build. The required-check ruleset uses the observed GitHub Actions integration and both matrix contexts. Superseded pull-request runs cancel; main and manual runs retain their evidence.

Main pushes and manual runs run the complete test inventory, v2 acceptance tests included, in four Node shards (database; unit and local; isolate with the backend image; browser with all three engines), and all four security partitions. These heavy checks run independently of both fast lanes. No local, database, isolate, browser, or security coverage is removed. JavaScript security partitions still prove complete standard-query coverage, alongside Python and Actions analysis. A manual security proof disables SARIF upload, preserves its proof artifact, and cannot deploy.

Deployment requires the entire `fast` matrix, Node, and security jobs to succeed for the same workflow run on main. Failed, cancelled, skipped, missing, or incomplete dependencies cannot authorize deployment. Security must verify the stored upload's exact commit, ref, category, and rule count. The deployment archives and sends that workflow's exact checked SHA. Main and manual runs share the existing ref concurrency group, keeping deployment runs serialized. GitHub may replace an older pending run with a newer pending run; active main and manual runs are not cancelled.

The fast-gate target remains strictly less than 120 seconds from submission through completion, including queueing and dependency setup. The previous full test gate measured 109 seconds. That measurement concerns the earlier, broader scope. With dependencies installed locally and warm caches, validation took 1.85 seconds and the pure test suite took 1.43 seconds. The first sequential hosted fast gate completed in 54 seconds, including four seconds of initial queueing, approximately 18 seconds of cold validation, and 14 seconds of pure tests. The first parallel run, on pull request #16 with warm TypeScript metadata, completed both checks in 34 seconds from submission, including queueing and setup. These measurements describe individual runs and do not guarantee future completion times. Heavy checks, provider security processing, and deployment are measured separately. Concurrent runner seconds are a cost measure rather than elapsed time.

The unused `scripts/ci/report-timing.js` helper reports observation time and does not enforce or measure completion of the fast merge gate.
